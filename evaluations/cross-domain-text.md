# 跨领域前向文字测试

日期：2026-11-03 UTC。对象：`anthropic-calm-ui` 当前 SKILL.md，以及 `references/patterns.md`、`references/theme-behavior.md`。

方法：读完上述指导后，分别直接回答六个模拟但现实的请求。仅交付设计方案，不创建页面、不运行界面、不改变任何外部状态。以下不是实际 UI、可用性测试、A/B 实验或效率提升证据。没有现有截图、代码或真实业务数据，因此不能把评审建议称为已确认缺陷。

## 1. 蓝色品牌中文科学刊物：从零建首页、专题、文章站，不加账户

1. **结构服务阅读。** 首页以本期重点文章、学科栏目和最新文章组织；专题页给出专题导语、文章顺序与关联主题；文章页包含标题、作者、日期、正文、图注及来源。共享刊名导航和面包屑，建立首页 → 专题 → 文章及返回路径，不添加登录、账户或无关销售模块。
2. **蓝色与中文排版成为识别点。** 采用白色阅读面与蓝色栏目标识、链接和选中态，正文深色；标题先用清晰中文无衬线，通过字重、段落间距和版面比例形成编辑气质，只有实际文章试排支持时才加入宋体。正文初始行宽约 32–38 个汉字作为试排起点，窄屏按设备自然缩减，不把大英文标题尺度直接套给汉字。
3. **节奏由内容而非空白堆出来。** 首页重点文章可以占较大版面，最新内容则保持紧凑、易扫读；长文用小标题、图表和解释性图注形成停顿，不把每段包成卡片。仅长专题或长文考虑目录，不让它压缩移动端正文。
4. **内容和前端边界诚实。** 未提供稿件时使用明确标注的样稿、示意图表与待补来源，不编造研究结论或引用。只建立三类必要页面和共享文章组件，不添加账户、付费订阅或假搜索能力。
5. **本轮验收重点。** 检查长中文标题、中英混排、公式溢出、图表窄屏阅读、正文放大和键盘链接路径；蓝色链接与正文区分且满足实际对比要求。当前交付为方案，上述检查需在实现后执行。

## 2. 鲜橙与洋红音乐节营销站：重设计，保留票务链接，不新增支付

1. **先保留可用资产。** 沿用现有音乐节名称、鲜橙与洋红品牌、演出信息、导航和票务 URL；先盘点各购票入口的目标地址与参数，重设计后逐一核对。页面核心路径为了解阵容、确认日期地点、进入现有票务站，不新增站内支付或结账。
2. **把强烈色彩留给有意义的区域。** 首屏主视觉、艺人照片与日程分区可大胆使用橙色和洋红；日期、地点及说明放在干净、对比清楚的阅读面。两种强色不同时争抢每个按钮，购票操作拥有稳定外观，日程选中态再配文字或形状。
3. **节奏不等于安静到失去现场感。** 用大幅演出图像与紧凑日程交替组织内容；大标题表达音乐节个性，导航、时间和票务说明使用清楚的无衬线。只保留实际已有或确有内容的栏目，不凭空添加赞誉、倒计时或售罄压力文案。
4. **动效帮助表达而不妨碍找信息。** 可对已有的舞台视觉、图片切换做有限动态设计，但不持续晃动日期、票务按钮，不劫持滚动；提供减少动态的呈现。移动端让日期、地点和购票入口容易找到，不用巨型主视觉挤掉关键内容。
5. **验证与暂不做。** 核对所有现有票务链接、焦点顺序、鲜色叠加文字的对比和移动端长艺名换行；检查减少动态设置。暂不新增支付、账户或新的票务逻辑。没有截图与运行证据前，不宣称转化率改善。

## 3. 绿色户外商店：商品列表和详情，只做前端，明确演示数据

1. **列表服务比较。** 用绿色品牌导航与清晰商品网格，优先呈现图片、名称、演示价格、核心规格和演示库存状态。筛选围绕示例商品真实具备的属性设计，例如用途、容量和重量，不为了外观添加无数据支撑的选项。
2. **详情服务判断。** 页面依次呈现商品图、名称、演示价格、规格选项及关键使用信息，详细参数用对齐列表或表格展示。保留比较所需密度，不用大片留白隐藏重量、尺寸或已知限制；不虚构用户评价、认证或实际配送承诺。
3. **保留户外品牌的生命力。** 自然场景图片与绿色承担品牌表达，规格区使用朴素背景、深色文字和少量分割线。选中尺码、无库存与错误同时用文字或标记表达，不让绿色情绪色兼任所有状态。
4. **明确前端演示范围。** 列表和详情共享同一套演示商品数据，页面明显标注“演示商品与价格，不支持下单”；筛选、排序、选规格可以在前端运行，不设置会暗示真实支付或真实库存的成功消息。没有购物车需求就不顺带添加。
5. **本轮检查。** 用长商品名、多规格、无库存、空结果和缺图样本验证；窄屏筛选要可触达且结果数量可见，返回列表时尽量保留已实现的筛选状态。所有对比、交互和布局结果待真实实现后验证。

## 4. 深紫音频创作应用：从零做作品库、编辑器、导出页，只前端

1. **先串通三个页面的任务。** 作品库用于选择和打开演示作品；编辑器展示作品、轨道和属性；导出页汇总格式设置并可返回原作品。三页共享作品 ID、名称、当前状态和稳定导航，深链接应能打开对应演示作品，未知 ID 显示明确空态。
2. **深紫主题，不套黑白模板。** 用深紫画布、稍高亮度的操作表面和清楚的正文对比；品牌强调色用于当前工具或主要操作。轨道颜色用于区分内容，不取代轨道名、静音或选择标记；危险操作另有语义提示。
3. **不同页面采用不同密度。** 作品库保留封面、名称、时长等可扫读信息；编辑器把主要空间给时间轴和轨道，工具栏与属性区可以更紧凑；导出页采用清楚的分组表单与参数摘要，不做巨型宣传标题。控制区克制，作品区保留必要的动态播放反馈。
4. **如实交付前端能力。** 演示作品、波形及未接通的能力明确标注。选择、缩放和参数编辑可在前端实现；未实现音频渲染时按钮标为“预览导出设置”，不显示“已导出”或伪造下载。没有持久化就显示“仅当前会话”，不声称云端保存。
5. **验证任务连续性。** 覆盖长作品名、无作品、跨页返回、键盘操作、播放/暂停呈现及窄屏工具布局；确认编辑值在已承诺的前端范围内保持一致。未保存离开的提示策略只针对实际存在的编辑能力设计，不伪装成完整生产级创作系统。

## 5. 已有蓝色多页运营后台：重设计，保留筛选、路由与业务

1. **以现有能力清单为边界。** 先记录页面路由、侧栏项目、筛选字段、表格列、批量操作与状态语义；保留原数据模型、筛选逻辑、查询参数和业务行为。视觉修改映射进现有 token 与组件，不迁移框架或另建平行组件体系。
2. **蓝色保持身份与操作一致。** 保留蓝色主操作、选中导航或品牌标识，表格用中性背景和清楚文字。减少每行操作按钮的竞争，但仍让高频操作易发现；不因“克制”降低异常、待处理或风险状态的显著程度。
3. **紧凑但不拥挤。** 页名、主要动作与关键说明形成短页头；筛选、搜索、结果数保持稳定分组。若现状确有无任务价值的装饰区，才建议缩短；不未经核实就删除统计卡。用对齐、行分割和一致数值格式改善扫读，不把数据表改成低密度大卡片。
4. **跨页一致而非全部同形。** 共享导航、过滤控件、状态标签和详情返回入口采用一致视觉；详情页仍按其任务组织字段。保留原筛选及分页状态的既有行为，不把重新分组控件当成修改业务规则的机会。
5. **回归先于风格宣称。** 逐页核对筛选结果、排序、分页、深链接与原业务操作；检查键盘路径、长文本和窄屏横向滚动，不能暗中丢列。新发现的缺失重试或防重复提交机制列作待确认项，不顺手加逻辑；没有用户研究就不宣称运营效率已提升。

## 6. 已有深色删除确认弹窗：仅评审，不写代码、不改行为

1. **范围与证据。** 只评审该弹窗的视觉层级、文案可理解性和状态呈现，不改代码、关闭方式、焦点管理或删除流程。尚无截图和实际文案，因此下面是评审标准，不是对现有弹窗已确认的问题清单。
2. **保留深色和危险语义。** 检查弹窗表面是否与遮罩、底层页面形成足够层次，正文、小字、边界与按钮在实际背景上的对比是否可读；不建议为了“像 Anthropic”改成米白。危险操作应有明确标签，不只靠红色识别。
3. **层级为判断服务。** 标题直接说出删除对象，正文清楚说明影响和现有恢复能力；不应使用“确定吗”取代关键后果，也不能添加不存在的撤销承诺。取消与删除可区分且易辨认，删除不应被装饰性插画或大段说明挤出可见区域。
4. **交互只记录，不擅改。** 核查现有焦点进入/返回、键盘可达性、提交中及失败状态是否有证据支持；特别记录 Esc、点击遮罩和默认焦点的当前策略，不机械建议全部改成可关闭或默认聚焦某个按钮。若需要改变行为，单独列出原因供后续决定。
5. **给出有边界的评审结果。** 收到截图后可标记可见层级与文字问题；收到可运行界面或测试记录后再判断焦点与状态行为。结论分为本轮必须解决的已证实阅读障碍，以及需补证据或另行授权的问题，不发起全站重设计。

## 简短结论

- **文字层面的六项适配均成立。** 蓝色中文刊物、鲜橙/洋红音乐节、绿色商店、深紫创作应用、蓝色高密度后台与深色局部弹窗，输出没有回落为统一米白、衬线或低密度模板。
- **共性仍有辨识度。** 六项都把阅读/扫读路径、内容主次、少而有意义的边界、清楚文案和任务对象置于装饰之前；人文感主要体现为尊重阅读、避免误导和保留品牌性格，而不是固定“温暖色”。音乐节仍可强烈，编辑器与后台仍可紧凑。
- **范围支持有效。** 新建可定义必要页面与共享结构；多页考虑返回和状态；重设计保护现有业务与链接；局部仅评审能够明确停在建议层。前端演示边界没有自动扩张为支付、账户或云端保存。
- **重要限制：本组题与内置例子高度重叠。** 刊物、商店、音频工具和后台直接接近 patterns.md；这能检验指导的一致执行，不能强证从未见领域的泛化。音乐节和深色仅评审弹窗提供少量组合迁移压力，但还应另测旅行搜索、地图、儿童学习或医疗信息阅读等未列领域。
- **没有发现必须修复的自相矛盾。** 可改进点是继续强调“只看截图不能验证键盘/业务行为”，并在未来实现测试中检查真实多页状态、色彩对比和中文排版。SKILL 已要求披露未验证项，现阶段不必为了补齐检查表继续膨胀正文。
- **结论级别：前向文字演练通过，不等于真实界面质量通过。** 未生成 UI、未渲染、未运行、未测用户表现；无法证明视觉质量、可用性或转化/效率改善。

# Anthropic-inspired Frontend Design

这是跨领域的前端设计 skill，适用于不同网站、应用与组件，不面向某个行业或业务流程。
把「平静、清楚、内容优先」转成可实施决策；平静指减少无关竞争，不要求低饱和、少内容、米白或衬线。持续保留 Anthropic 启发的阅读节奏、内容主次、视觉克制与人文感；按项目调节表达，而不是退化成无方向的通用清单。鲜明品牌、必要信息密度与有目的的表现力可以与这些原则共存。

## 证据边界

- 本 skill 是受公开界面启发的独立方法，不是 Anthropic 官方设计系统；不复制商标、插画、字体文件或专有素材。
- 区分官网、产品宣传预览与真实应用。公开页面观察不能证明登录后工作区、移动端或完整交互行为。
- 字体按内容角色选择；主题与页面分区分别检查。不要把“浅色首页”或“衬线标题”推广成全产品规则。
- 示例 token、尺寸、间距、断点和时长都是独立适配建议，不是官方规范或完整原站测量。
- 需要依据时阅读 [历史观察与来源](references/evidence.md)；涉及系统深浅色、局部反色区时阅读 [主题复核](references/theme-behavior.md)。保留各记录的时间、覆盖范围与未验证项。

## 先选界面模式

先确定受众、核心任务、内容形态、品牌语气、输入设备和成功条件，再决定视觉方向。区分新建、重设计、局部调整和仅评审：新建可建立必要结构，重设计先界定保留项，局部调整不扩展范围，仅评审不改代码。新页面从真实内容与目标出发；现有页面先识别必须保留的设计资产与行为。判断用户在理解、探索比较、创作、完成任务还是高频操作；以下模式不是固定页面模板，可混合使用。

| 模式 | 借鉴重点 | 不该照搬 |
| --- | --- | --- |
| 编辑式官网 / 内容页 | 有辨识度的标题、阅读宽度、章节节奏、少量强 CTA | 把正文也变成巨型标题；每屏只有一句话 |
| 生产力应用 | 安静工作区、任务焦点、可预测控件、低干扰辅助信息 | 把登录首页的居中卡片复制到复杂工作台 |
| 数据后台 | 扫读、列对齐、紧凑但清晰的行、稳定工具栏 | 巨量留白、卡片套卡片、表格改成宣传页 |
| 消费产品 / 浏览比较 | 内容、图片、差异和决策信息可扫描 | 为极简隐藏价格、规格或筛选 |
| 创作 / 品牌体验 | 有目的的视觉个性、作品与控制界面分工 | 把所有品牌都改成安静米白模板 |
| 移动 / 触屏任务 | 内容优先、易触达动作、即时反馈 | 依赖 hover、照搬桌面密度 |

有已有侧栏就评估它是否服务任务，不因风格移除；没有侧栏也不为「像 Claude」而新增。
跨领域示例与取舍见 [references/patterns.md](references/patterns.md)。需要初始化样式变量时再读 [references/tokens.css](references/tokens.css)；示例颜色的计算范围、随附验证脚本用法与局限见 [references/validation.md](references/validation.md)。

## 核心设计决策

### 先分清主次，再增加留白

- 每个任务区域设清楚的主要操作；全页可以有多个任务区域，勿机械地限制全页只有一个按钮。
- 主次依次用位置、分组、字号/字重、间距、颜色区分，不靠给所有块加阴影。
- 同组元素靠近，组间拉开；留白必须帮助理解或操作，不以屏幕空旷为目标。
- 生产力页面优先让工作对象可见。减少装饰性页头，而不是把关键内容挤到首屏以下。
- 有业务必要的状态、数字、警告保持明显，不以「克制」之名降级它们。

### 字体对比：表达层与操作层分开

- 字体按内容角色配对：编辑式页面可用衬线标题，也可用无衬线标题配衬线长文；输入、导航、表格和小标签优先清晰的无衬线。
- 中文界面不要直接把英文标题字号和字距套进汉字。按品牌与阅读目标选择合适中文字形，系统宋体/明朝体只是可选表达，正文优先验证可读性而不是固定字体类别。
- 字体未安装时用系统回退，不下载未经许可的商业字体，不依赖联网字体才能保持布局。
- 小中文不加宽字距，不堆过细字重；多行标题按真实文本检验换行，不用固定高度硬截断。
- 数据列用等宽数字；数字右对齐、文本左对齐。金额、日期与状态的扫描效率优先于装饰。
- 为长中文、英文混排、空值和大数字验证布局，而非仅用短占位文本。

### 配色：分配角色，不铺一层米色

- 先从现有品牌、内容和产品语义确定色彩角色。暖白与近黑只是可选示例，不是默认替换方案；鲜明彩色、纯白或深色都可采用，关键是层级与实际对比。
- 已有或用户要求的深色主题应保留：沿用适合品牌的暗色调和清晰语义色，不强制深炭色、暖白或整体反相。示例深色变量是建议，不是观察到的 Claude 深色 UI。
- 建立画布、表面、正文、次要文字、边界、主操作、焦点、成功、警告、危险的语义角色。
- 区分全局主题与局部反色区：浅色主体可以搭配深色页脚或强调区。先检查主要分区及其文字/控件颜色，不用 body 背景概括整页，也不把一个深色区当作已启用系统深色模式。
- 既有品牌色可保留为主操作或选中态；不强制把它替换成陶土橙。
- 暖灰可用于装饰性分割，不默认适合小字。实际前景/背景组合需要检查对比。
- 错误、成功和选中状态同时使用文本、形状或图标，不只用颜色表达。
- 原站的视觉印象不是可访问性证明；不要复用未经验证的低对比组合。

### 边界：用最少的层次表达真实关系

- 靠背景、间距或一条分割线能说明关系时，不再套卡片。
- 圆角随对象角色变化：按钮与输入协调；对话框可以更柔和；表格无需逐行圆角。
- 阴影用于悬浮、遮挡或层级，不给每张静态卡片同样的漂浮感。
- 优先复用已有组件，避免为微小外观差异创建一套平行组件体系。

### 交互：安静，但不含糊

- 主要动作明确；次要动作降权但仍易识别。破坏性操作保留必要确认或可恢复路径。
- 覆盖默认、hover、pressed、focus-visible、disabled、loading、selected 与 error；按组件适用状态实现。若用户只授权外观修改，保留现有行为，将缺失的重试、防重复提交等机制列为待办，不顺带新增业务逻辑。
- 禁用原因或替代路径可发现；加载显示正在做什么，防止重复提交；失败提供重试或下一步。
- 输入保留可见标签；占位符不能代替标签。错误放在相关字段附近，保持已有输入。
- 键盘焦点不能只靠细微颜色改变；使用清晰外轮廓，不取消原生 outline 后忘记替代。
- 动效可服务状态解释、空间关系或有目的的品牌表达；尊重 reduced-motion，避免无意义的持续运动和滚动劫持，不因“克制”抹掉创意项目有依据的动态设计。
- 焦点管理、对话框关闭、屏幕阅读器名称等沿用现有成熟组件，不为样式重写行为。未保存输入、提交中或不可逆操作的关闭策略按业务决定，不统一改成点击遮罩或 Esc 即关闭。

## 轻量实施流程

### 读现状，做一个小决定

- 先看当前截图、关键任务、已有组件和样式变量；缺一项不等于要开展全面重构。
- 用一句话说明本次受众、任务、视觉方向和范围；先解释为何适合内容，不先挑米色或卡片模板。
- 按用户要求交付建议、设计或可运行前端。新建请求可建立必要页面与组件；已有项目优先沿用其技术栈。未获请求时不要把审阅变成新项目、迁移框架或新增依赖。
- 对未明确的非关键偏好采用合理默认；只有会改变核心方案的缺口才提问。

### 按范围实施

- 从零建站：根据真实内容决定页面和章节、导航及主要行动，建立最小语义样式与可复用组件；不要默认添加 hero、定价、评价、仪表盘等与任务无关的模块。
- 多页应用：先明确任务路径、路由与共享导航，区分全局组件和页面特例，验证跨页状态、返回路径和深链接；未提供后端时明确标注示例数据和未连接能力，不伪装真实提交。
- 局部修改：沿用现有结构，只改用户指定范围；新建和局部改造都不应由风格自动决定产品架构。

- 新设计先确定内容结构与主要任务路径，再实现视觉与交互；局部改进先选指定页面或组件，不把本地问题扩大成全站改造。
- 将必要变量映射进已有 token 体系；不要直接粘贴整套示例 CSS 覆盖全局。
- 没有 token 体系时，仅增加本次需要的变量；不建立超过当前需求的设计平台。
- 保留路由、业务规则、数据模型和用户熟悉的导航。确需改信息架构时先说明原因与范围。
- 以真正内容验证，不新增无业务意义的指标、营销文案、菜单或漂亮空模块。

### 验证并收尾

- 检查窄屏、宽屏、长内容、键盘路径、缩放、加载、空白与错误状态；按本次界面需要取样。
- 不把桌面压缩等同于移动适配：工具栏可换行；表格可保留有标识的横向滚动；不可默默丢列。移动表单还需检查软键盘弹出后的当前字段与提交入口、安全区、视口变化和错误定位。
- 检查普通文字对比至少 4.5:1、大字至少 3:1（约 24 CSS px 常规字或 18.67 CSS px 粗体）；识别控件和状态必需的非文本视觉信息与相邻颜色至少 3:1（不把装饰分割线或禁用态机械套入）；这些是验收门槛而非原站测量。
- 触控目标根据设备、使用距离和误触风险设定；同一产品的移动触控与桌面指针界面不必采用同一密度。
- 若可运行，沿用项目已有构建/测试方式；没有截图或浏览器证据时，明确哪些检查尚未完成。
- 建议分成「本轮必做」和「暂不做」，优先解决主任务的阅读与操作障碍，不把完整检查清单自动变成开发需求。
- 交付实际改动、最关键的设计理由和剩余问题。当前范围已满足就停止，不自动发起下一轮重设计。

## 避免这些误解

- 「像 Anthropic」不等于米色 + 衬线 + 超大圆角。
- 「高级」不等于小字、浅灰、低对比、不可见控件。
- 「极简」不等于隐藏业务信息或删除用户需要的操作。
- 「通用」不等于宣传页、商店、创作工具与数据表采用同一美学或密度。
- 「完善」不等于必须先重建全站设计系统。
